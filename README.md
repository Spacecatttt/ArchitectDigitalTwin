# Платформа цифрового двійника обробного центру з ЧПК

Лабораторна робота 1 «Архітектурний опис та моделе-орієнтована модель платформи цифрового двійника», дисципліна «Архітектури імерсивних систем та платформ цифрових двійників», КПІ ім. Ігоря Сікорського, ФПМ, кафедра ПЗКС. **Варіант 3 — верстат із ЧПК.**

## Об’єкт

3-осьовий вертикально-фрезерний обробний центр (шпиндель до 12 000 об/хв, 15 кВт) з ЧПК SINUMERIK 828D (вбудований OPC UA-сервер), доповнений акселерометром на шпинделі, двома Pt100 і модулем DAQ. Платформа — **цифрова тінь**: у реальному часі відображає стан верстата, виявляє автоколивання й перевантаження шпинделя, оцінює знос інструмента, зберігає історію та формує звіт за зміну. Керувальних команд у ЧПК не надсилає — режим змінює оператор за рекомендацією.

Ключові числа: 13 сигналів, 905,9 МБ телеметрії на добу (95,4 % — вібрація 5 кГц); покриття ISO 23247 C = 88,9 %; наскрізна затримка 440 мс (середнє) / 661 мс (p95) → гіпотеза Г-01 (WebSocket push) знижує p95 до 216 мс; покриття вимог C_т = C_в = 100 %.

## Мова моделі

**SysML v2** — текстова нотація, SysML v2 Pilot Implementation (ядро Jupyter `sysml`, перевірено версією 0.62.0).

## Як переглянути модель

**Без встановлення:** відкрийте в браузері `model/export/model.html` — це експорт виконаного блокнота з текстом моделі й усіма діаграмами. Окремі діаграми: `model/export/*.svg`:

| Файл | Що показує |
|---|---|
| `requirements_diagram.svg` | вимоги FR/NFR, згруповані за доменами ISO 23247 |
| `platform_bdd.svg` | склад блоків платформи (аналог BDD) |
| `platform_ibd.svg`, `edge_gateway_ibd.svg` | порти та з’єднання (аналог IBD) |
| `process_sample_activity.svg` | діяльність: відлік → валідація → оновлення стану → сповіщення |
| `machine_state.svg` | стани верстата, що відстежує двійник |

**Інтерактивно:** встановіть SysML v2 Pilot (Java 21+, Miniconda; `install/jupyter/install.sh` з релізу SysML-v2-Release або `conda install -c conda-forge jupyter-sysml-kernel`), потім:

```
jupyter lab model/model.ipynb
```

і виконайте всі комірки (Run → Run All Cells). Після зміни `CncMachineTwin.sysml` блокнот перезбирається: `python model/build_notebook.py`.

## Як відтворити розрахунки

```
python3 docs/volume.py        # добовий обсяг телеметрії
python3 docs/latency.py       # затримка, Монте-Карло, чутливість, гіпотеза Г-01
python3 model/trace_check.py  # C_т, C_в і узгодженість ідентифікаторів
```

Потрібен лише Python 3.9+ (стандартна бібліотека; `trace_check.py` — також).

Рендеринг діаграм Mermaid:

```
cd docs/diagrams
for f in context components deployment dataflow; do npx -y @mermaid-js/mermaid-cli -i $f.mmd -o $f.svg; done
```

## Архітектурні подання (ISO/IEC/IEEE 42010)

| Подання (view) | Точка зору (viewpoint) | Зацікавлена сторона | Інтерес (concern) | Файл |
|---|---|---|---|---|
| Контекстне | контекстна: система як «чорна скринька» серед людей і суміжних систем | ЗС-1 оператор, ЗС-4 майстер, ЗС-2 технолог | хто користується платформою, які дані отримує, з якими системами обмінюється | `diagrams/context.mmd` |
| Компонентне | функційна / логічна декомпозиція | ЗС-6 розробник, ЗС-2 технолог, ЗС-3 інженер з обслуговування | з яких складників складається платформа, де реалізована кожна функція, як складники взаємодіють | `diagrams/components.mmd` |
| Розгортання | фізична / інфраструктурна | ЗС-5 адміністратор ІТ/ОТ, ЗС-6 розробник | на яких вузлах і в яких мережевих зонах працюють складники, які порти й протоколи відкрито, як масштабувати | `diagrams/deployment.mmd` |
| Потоку даних (модель інформаційних процесів) | інформаційна / процесна | ЗС-1 оператор, ЗС-6 розробник | маршрут відліку, перетворення на кожній ділянці, затримки, паралельні гілки | `diagrams/dataflow.mmd` |
